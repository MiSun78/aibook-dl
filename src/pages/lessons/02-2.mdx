<Sec id="s1" title="기계학습 모델의 구현 과정" pages="92쪽">

<Split>
<div>

문제 정의에 따라 모은 데이터는 학습을 거쳐 기계학습 모델을 만드는 데 쓰인다. 기계학습 모델은 다음 네 단계로 만든다.

**단계 1 문제 정의하기**: 해결할 문제를 분명히 이해하고 목표를 정한다. 기계학습으로 풀 수 있는 문제인지, 지도학습과 비지도학습 중 어느 쪽으로 풀 문제인지 판단해 기계학습의 관점에서 문제를 정의한다.

**단계 2 데이터 수집 및 전처리하기**

1. 데이터 수집하기: 직접 만들거나 측정하거나, 이미 있는 데이터를 쓴다. 데이터의 양과 품질을 확인한다.
2. 탐색적 데이터 분석하기: 통계와 시각화로 데이터의 속성을 파악한다.
3. 데이터 전처리하기: 결측치와 이상치를 처리하고 학습에 알맞게 가공한다.
4. 핵심 속성 추출하기: 탐색 결과로 모델에 쓸 핵심 속성을 고른다.

**단계 3 모델 생성하기**: 문제에 알맞은 기계학습 유형과 알고리즘을 골라 모델을 만들고, **훈련 데이터**로 학습시킨다.

**단계 4 모델 평가하기**: **테스트 데이터**로 모델의 성능을 평가한다. 필요하면 단계 3으로 돌아가 모델을 고친다.

</div>

|---|---|---|
| 지도학습 | 분류 | 결정트리, k-최근접 이웃, 로지스틱 회귀, 퍼셉트론, 다층 신경망 |

**문제 상황**: 빈 병과 페트병을 자동으로 분류해 포인트를 적립해 주는 인공지능 자판기가 있다. 그런데 라벨이 붙은 페트병과 라벨을 뗀 페트병은 구분하지 못한다. 두 가지를 구분하는 모델을 만들어 보자.

| 단계 | 할 일 |
|---|---|
| 단계 1 문제 정의하기 | 생수병을 라벨(label), 무라벨(labeless) 두 클래스로 분류하는 모델을 만든다. |
| 단계 2 데이터 수집 및 전처리하기 | 라벨 생수병과 무라벨 생수병 사진을 직접 모으거나 교과서 링크의 '라벨-무라벨 생수병 분류하기.zip'을 내려받는다. 사진을 훈련 데이터와 테스트 데이터로 나눈다. |
| 단계 3 모델 생성하기 | [티처블 머신](https://teachablemachine.withgoogle.com/)에서 [이미지 프로젝트] → [표준 이미지 모델]을 고른다. 클래스 이름을 label, labeless로 정하고 훈련 데이터 사진을 올리거나 웹캠으로 찍는다. [모델 학습시키기]를 누른다. |
| 단계 4 모델 평가하기 | 학습이 끝나면 웹캠이나 테스트 데이터 사진으로 예측해 본다. |

<Sec id="s2" title="기계학습 모델의 학습과 평가" pages="94~95쪽">

기계학습은 사람이 배우는 과정과 비슷하다. 사람은 많은 사례로 개념을 익히는데, 사례가 틀렸거나 너무 적으면 개념을 제대로 알지 못한다. 그래서 잘 배웠는지 시험으로 확인한다. 기계학습도 정확하고 충분한 데이터로 학습하고, 따로 남겨 둔 데이터로 시험을 본다.

### (1) 기계학습 알고리즘 선정과 모델 생성하기

문제에 알맞은 모델을 만들려면 어떤 모델과 알고리즘을 쓸지 먼저 검토한다.

- **선형 회귀 모델**: 특징값으로 수치를 예측한다. 예) 공부 시간으로 성적 예측 → 96쪽
- **분류 모델**: 특징값으로 몇 가지 클래스 중 하나로 분류한다. 결정트리, 선형 분류, 비선형 분류 등이 있다. → 106쪽
- **군집 모델**: 비슷한 데이터끼리 묶는다. → 118쪽

### (2) 데이터를 이용해 모델 학습시키기

<Split>
<div>

**학습**은 고른 모델을 데이터에 맞추는 과정이다. 즉, 주어진 데이터로 모델의 매개 변수(계수) 값을 조정해 모델이 성능을 잘 내게 만든다.

이때 전체 데이터를 학습에 쓸 **훈련 데이터**(train)와 성능을 평가할 **테스트 데이터**(test)로 나눈다. 테스트 데이터는 학습에 쓰지 않는다. 학습에 쓴 데이터로 시험을 보면 실제 실력을 알 수 없기 때문이다.

</div>
<FigSplit />
</Split>

모델이 훈련 데이터에서만 성능이 좋고 다른 데이터에서는 성능이 떨어지는 것을 **과적합**(overfitting)이라고 한다. 예시 문제의 답만 외워서 새 문제는 못 푸는 것과 비슷하다. 반대로 모델이 너무 단순해서 훈련 데이터의 패턴조차 제대로 배우지 못하는 것은 **과소적합**(underfitting)이다. 훈련 데이터와 테스트 데이터 모두에서 성능이 좋도록 오류를 줄여 가는 과정을 **최적화**(optimization)라고 한다.

<Ask>

- 차수를 1부터 9까지 올려 보자. 훈련 오차는 어떻게 변하는가? 테스트 오차는 어떻게 변하는가?
- 훈련 오차가 0에 가까운데도 좋은 모델이라고 할 수 없는 까닭은 무엇일까?

</Ask>

과적합되지 않은 모델을 만드는 대표적인 방법이 **교차 검증**(cross-validation)이다. 훈련 데이터를 여러 조각으로 나누어 한 조각은 **검증 데이터**로, 나머지는 훈련에 쓰는 것을 조각을 바꿔 가며 되풀이한다. 검증 데이터에서 성능이 나쁘면 과적합을 의심할 수 있다.

### (3) 모델 평가하기

완성한 모델의 최종 성능은 여러 척도로 평가한다. 데이터가 충분하면 훈련 데이터에서 검증 데이터를 따로 떼어 만드는 중에 성능을 확인하고, 최종 성능은 테스트 데이터로 잰다. 데이터가 넉넉하지 않으면 훈련 데이터와 테스트 데이터로만 나누고, 아주 적을 때는 교차 검증에서 얻은 성능을 평갓값으로 쓰기도 한다.

</Sec>

<Sec id="more" title="k-폴드 교차 검증" pages="95쪽" kind="더 알아보기">

<Split>
<div>

**k-폴드**(k-fold) **교차 검증**은 훈련 데이터를 k개의 조각(폴드)으로 나누어 k−1개로 훈련하고 남은 1개로 검증한다.

k=5이면 훈련 데이터를 5등분해 1개는 검증, 4개는 훈련에 쓴다. 검증 조각을 바꿔 가며 훈련과 검증을 모두 다섯 번 하고, 다섯 평갓값의 평균을 모델의 성능으로 추정한다. 데이터를 한 번만 나눌 때보다 우연에 덜 흔들리는 성능을 얻을 수 있다.

</div>
